# [071] BUG - Client Name and Client Code must be unique

**Board status:** Ready

## Background

**This is `blackwell-backend` work.**

Found during manual testing of [061]/[062] (Client Create page, Edit Client page). `createClient.ts` only validates `clientCode` uniqueness via `validateClientCodeIsUnique` — `clientName` isn't checked at all. `updateClient.ts` has no uniqueness validation whatsoever, for either field — a client can currently be renamed/recoded to collide with another existing client.

The frontend already surfaces the backend's own error message via `resolveErrorMessage` on both the Client Create page ([061]) and the Client Info edit page ([062]), so no frontend change is needed here — a corrected backend message will just show up.

## Scope

- `src/services/client/validateClientCodeIsUnique.ts` — add an optional `excludeClientId` param, so a client keeping its own unchanged code doesn't trip the check during an update
- New `src/services/client/validateClientNameIsUnique.ts` — same shape/behavior as the code validator, for `clientName`
- `src/services/client/createClient.ts` — call `validateClientNameIsUnique` alongside the existing `validateClientCodeIsUnique` call
- `src/services/client/updateClient.ts` — fetch the full client list (`readClients`) and run both validators against the merged `updatedClient`, excluding its own `clientId`, before `writeClients`
- Extend unit tests: `validateClientCodeIsUnique.test.ts` (excludeClientId behavior), new `validateClientNameIsUnique.test.ts`, `createClient.test.ts` (clientName collision case), `updateClient.test.ts` (clientCode/clientName collision cases, and that updating a client to its own current values doesn't throw)
