# [058] Validation: salaried employee with zero salary-hours

**Board status:** Backlog
**Part of:** [048] Expand EmployeeActivityRates (Epic)
**Depends on:** [057]

## Background

**This is `blackwell-backend` work.**

If a salaried employee logs zero hours against `salary`-type activities in a pay period, [057]'s `salaryAmount / totalEligibleHours` division has no denominator. Decided: this is a new, standalone validation (not an extension of any existing check) at payroll-report-generation time, since that's already where hours are first fully known and where similar checks exist (e.g. the existing "hours logged but marked not included in payroll" check in `generatePayrollReport.ts`).

## Scope

- In `generatePayrollReport.ts` (or `generateAllocationReport.ts`, whichever runs the salary calc from [057]), add a per-employee check: if the employee has any `salary`-type bridge rows and zero hours logged against all of them for the pay period, throw an `UnprocessableError` naming the employee, before allocation runs
- This is deliberately at report-generation time, not at timesheet completion/signing time
