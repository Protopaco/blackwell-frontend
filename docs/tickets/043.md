# [043] BUG - Pay Period dashboard shows holidays outside the pay period's date range

**Board status:** Backlog
**Reported:** 2026-07-27

## Background

**This is `blackwell-frontend` work.**

On the Pay Period dashboard, `HolidaysCard` (`src/components/PayPeriodDashboard/HolidaysCard/HolidaysCard.tsx`) renders whatever is in `payPeriodConfig.holidays` with no filtering — it just maps the array straight into a `DashboardList`. That array comes from `payPeriodApi.v1GetPayPeriodConfig` (fetched in `PayPeriodLayout.tsx`), i.e. a snapshot taken at pay period creation (or last "Sync").

The backend's `v1SyncHolidaysOnPayPeriod` endpoint (triggered by the card's "Sync" button) does filter to holidays whose date falls within the pay period's `startDate`/`endDate` — but that only runs when the user manually clicks Sync. Until then, the snapshot can contain holidays outside the pay period's range (e.g. if the client's holiday list changed since the snapshot was taken), and the frontend has no independent date-range check to catch that — it displays the snapshot as-is.

Result: the card can show holidays that aren't actually within the pay period being viewed.

## Scope

Filter the holidays list in `HolidaysCard.tsx` (or wherever it's cleanest) to only those with `holidayDate` within `[payPeriod.startDate, payPeriod.endDate]` before rendering, rather than trusting the snapshot to already be correct. `payPeriod.startDate`/`endDate` are already available via the pay period fetch. Not yet decided: whether this client-side filter fully replaces the need for the manual "Sync" step, or whether "Sync" still matters for reasons beyond display (e.g. keeping the persisted snapshot itself accurate) — worth confirming before implementing.
