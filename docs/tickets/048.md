# [048] Expand EmployeeActivityRates (Epic)

**Board status:** Ready (epic — tracked as a group, broken into tickets 049-058)

## Background

**This is `blackwell-backend` work.**

Today, pay rates live in the wrong places: `Employee.hourlyPayRate1`, `hourlyPayRate2`, `holidayPayRate` on the employee, and `Activity.payRate`/`flatRateAmount` on the activity. This structurally assumes every employee is eligible for every activity at the same rate, which doesn't hold — real clients have per-employee, per-activity pay exceptions.

Replacing this with a proper bridge: a new `EmployeeActivityRates` tab in each client's PayrollConfig workbook, one row per `(employeeId, activityId)` pair, carrying its own pay type and rate. No employee/activity pairing currently exists anywhere in the system (pay periods snapshot the full Employees and Activities tabs independently — see [049]/[053]), so this is new plumbing, not a refactor of an existing join.

No existing clients — pre-launch, so no migration or back-compat path needed. Old rate fields are removed outright, not deprecated.

### Bridge row shape (decided)

`id, employeeId, employeeName, activityId, activityName, payRateType (hourly/flatrate/salary), payRate, holidayPayRate`

`employeeName`/`activityName` are for human readability in the sheet only — all matching/logic uses the IDs.

### Salary (decided)

New `salaryAmount` field on Employee (presence/nonzero = salaried, no separate boolean). Per pay period: `effectiveHourlyRate = salaryAmount / hours logged against salary-type activities that period`, applied per salary-type activity. Hourly/flat-rate activities calculate independently and are additive on top (e.g. a salaried employee's paid on-call shift). A salaried employee with zero hours on salary-type activities for a pay period is a validation error at report-generation time, not a silent $0.

### Holiday pay (decided)

`holidayPayRate` was defined on Employee today but dead — nothing reads it. It's being reintroduced on the bridge row and actually wired into calculations this time: holiday-flagged hours use the bridge row's `holidayPayRate` instead of its normal rate.
