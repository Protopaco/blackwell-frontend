# [054] EmployeeActivityRates in pay-period snapshot workflow

**Board status:** Backlog
**Part of:** [048] Expand EmployeeActivityRates (Epic)
**Depends on:** [049]

## Background

**This is `blackwell-backend` work.**

Pay periods currently snapshot the full `Employees` and `Activities` tabs into their own report workbook at creation time (`createPayPeriodConfigSnapshot.ts`) — two independent copies, no pairing between them. The bridge needs the same snapshot treatment.

### Locking — clarified in epic discussion

`updateActivityOnPayPeriod.ts` today locks an activity's `payRate`/`flatRateAmount` once the first timesheet has been generated for that pay period — but that lock has only ever applied to the **pay-period-scoped snapshot copy** (edited via that pay period's own activity-edit endpoint), never to the master client-wide PayrollConfig `Activity`. Master config has always stayed freely editable.

The bridge follows the same rule: master `EmployeeActivityRates` rows (edited via [051]'s Employee endpoints) are **never locked** — a bookkeeper can always change an employee's rates. A pay-period-scoped edit/lock for bridge rows (mirroring `updateActivityOnPayPeriod.ts`) is a separate, later concern, out of scope for this epic, and not expected to be complicated when it's built.

## Scope

- Add `EmployeeActivityRates` as a third snapshot tab in `createPayPeriodConfigSnapshot.ts`, alongside Employees and Activities
- Update `readPayPeriodConfigSnapshot.ts` to read the bridge snapshot too
- No locking logic in this ticket — master rows stay freely editable, per above
