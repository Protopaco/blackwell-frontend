# [042] BUG - Direct/shared links to client pages 404 on Render

**Board status:** Backlog
**Reported:** 2026-07-27

## Background

**This is a deployment/hosting issue, not a `blackwell-frontend` routing bug.**

URLs like `https://blackwell-timekeeping-frontend.onrender.com/client/95d213a7-824d-4581-bb4a-53ee02b7936e` return "not found" when loaded directly (fresh navigation, page refresh, or a shared link) — even though `src/router.tsx` already defines this route (`client/:clientId`, and its sub-routes).

Root cause: this is a client-side (React Router) route, which only resolves once the SPA's JS has booted in the browser. On direct load, the request first hits Render's static-site host, which looks for a literal file/directory at `/client/<id>` and returns a real HTTP 404 before `index.html`/the app ever loads. Confirmed there is no `render.yaml` or `_redirects` file anywhere in the repo configuring a rewrite rule.

Only in-app navigation (clicking links after the SPA is already loaded) works, since that never round-trips through the static host.

## Scope

Add a catch-all rewrite so unmatched paths serve `index.html` (letting React Router take over client-side), e.g. a `render.yaml` rewrite rule (`source: /*`, `destination: /index.html`) or a `_redirects` file, depending on how the Render static site is currently configured. Needs deployment config, not a `router.tsx` change. Exact mechanism (render.yaml vs. dashboard-configured rewrite vs. `_redirects`) to be confirmed before implementing.
