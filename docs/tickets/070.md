# [070] Validation: require Settings fields on client create

**Board status:** Ready
**Part of:** [059] Client Management Workflow (Epic)
**Depends on:** [061]

## Background

**This is `blackwell-backend` work.**

While building [061] (Client Create page), it came up that `Settings`'s three fields (`timeInputMethod`, `payPeriodInterval`, `payPeriodStartDate`) are each individually optional in the OpenAPI schema, even though the parent `settings` object is required on `ClientCreateRequest`. `writeSettings` writes whatever it's given straight to the Settings tab with no validation or defaulting, so the API currently accepts `settings: {}` and silently creates a client with a blank Settings row.

There's no dedicated Settings edit UI yet ([008] Settings Management is still backlog) — `ClientSettingsCard` on `ClientSummary` is read-only. A client created with blank Settings would have no way to fix that gap until [008] ships. [061]'s UI will require these fields, but the backend should enforce it too rather than relying on the frontend alone.

## Scope

- `src/utils/swagger/schema/settings.ts` — add `required: ['timeInputMethod', 'payPeriodInterval', 'payPeriodStartDate']` to the `Settings` schema
- `src/services/client/createClient.ts` — validate `request.settings.timeInputMethod`/`payPeriodInterval`/`payPeriodStartDate` are all present, throwing `UnprocessableError` if not (same style as the existing `rootFolderLink`/file-collision checks in this file)
- Extend `createClient.ts`'s unit tests to cover the new validation
