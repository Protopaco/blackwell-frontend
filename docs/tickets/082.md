# [082] Split EmployeeExpenses `totalExpense` into `wageExpense` and `taxExpense`

**Board status:** Backlog
**Reported:** 2026-08-12

## Background

This spans both `blackwell-backend` and `blackwell-frontend`.

Per-employee expenses on the Payroll Report currently track a single `totalExpense` number. We need to
separate it into two fields, `wageExpense` and `taxExpense`, per employee per pay period. Not yet clear
how the two will be consumed downstream — in particular, `buildAllocationRows.ts` currently uses
`totalExpense` directly as the wage-allocation numerator (proportioned across funding sources by
hours-weighted cost, summed into `processedWagesTotal`). Whether that becomes `wageExpense` alone, the
sum of both, or something else needs to be resolved as part of this ticket — don't guess, confirm with
the client/business side before changing the allocation formula.

## Resolved decisions (2026-08-13)

- **Allocation approach**: wages and taxes are handled as two fully separate allocation lines, not
  combined. The bookkeeper's existing spreadsheet already does this — `% WAGES` (the existing
  hours-weighted funding-source percentage) is applied independently to both the wage total and the tax
  total, producing two parallel columns. The funding-source weighting logic itself is not duplicated or
  changed, just reused for a second numerator.
- **Allocation Report columns**, in order: `Funding Source`, `Wages Allocation`, `Taxes Allocation`,
  `Additional Expenses`, `Total`. New field name: `taxesAllocation` (matches the existing
  `wagesAllocation` naming pattern and the "Taxes Allocation" header text).
- **`allExpensesComplete` gating**: requires both `wageExpense` and `taxExpense` to be non-null — a
  half-entered split doesn't count as complete.

## Implementation plan

Broken into 6 sequential chunks, each independently buildable/testable — stop after each one for
review before starting the next.

1. **Backend rename** — `totalExpense` → `wageExpense` + `taxExpense` across models
   (`EmployeeExpense.ts`, `EmployeeExpenseUpdate.ts`), swagger schema, `EMPLOYEE_EXPENSES_HEADERS`, the
   `EmployeeExpenses` sheet tab (two columns instead of one), db read/write
   (`readEmployeeExpensesTab.ts`/`writeEmployeeExpensesTab.ts`), the update/merge/response services
   (`updateEmployeeExpenses.ts`, `updateEmployeeExpensesBatch.ts`, `mergeEmployeeExpenseTotals.ts`,
   `buildPayrollReportResponse.ts`), route JSDoc, devTestData seed. Pure mechanical split, no behavior
   change yet — `buildAllocationRows.ts` temporarily sums both fields together so report output is
   identical to today. Update existing tests referencing the old field name.
2. **Backend allocation logic** — add `taxesAllocation` to `AllocationReportRow`, update
   `ALLOCATION_REPORT_HEADERS`, rework `buildAllocationRows.ts` to compute `wagesAllocation` and
   `taxesAllocation` as two independent totals using the same funding-source weighting (including
   extending the last-row remainder-rounding to cover `taxesAllocation` too). New/updated unit tests for
   `buildAllocationRows.test.ts`.
3. **Backend integration tests + OpenAPI regen** — update the integration tests listed above, run
   `npm run generate` so `docs/openapi.json` reflects the new fields.
4. **Frontend generated client** — regenerate `src/api/generated/**` from the updated spec.
5. **Frontend Payroll Report table/page** — split the single currency input into two (`Wage Expense`/
   `Tax Expense`), update headers, dirty-diff logic, save payload, and `allExpensesComplete` gating (per
   the resolved decision above).
6. **Frontend Allocation Report table** — add the "Taxes Allocation" column to `AllocationReportTable.tsx`
   between "Wages Allocation" and "Additional Expenses".
