# [079] Read clock-in/clock-out timesheets with slot-row validation

**Board status:** Backlog
**Reported:** 2026-08-12
**Implemented:** 2026-08-13
**Depends on:** [078] (needs the `clockInOutWeeks` manifest shape), [080] (hours calculation)

## Background

**This is `blackwell-backend` work.**

Second piece of adding the clock-in/clock-out timesheet mode. `readTimesheetEntries.ts` branches on
whether the manifest's `clockInOutWeeks` is populated: instead of reading one hours cell per activity
row per day, it reads each day's slot rows (activity dropdown + Clock In + Clock Out) and validates
them, plus that day's Flat Rate rows if present.

The Sheet's own slot Total formula (from [078]) is **display-only** — not read by this code. Several of
the validation rules below require inspecting individual slot rows anyway (not just a summed total), so
the TypeScript read path is the authoritative source of truth for hours, computed independently via
[080]'s `calculateClockInOutHours`. This avoids two sources of truth silently drifting apart.

**Parsing raw cell values**: Google Sheets' read API defaults to `FORMATTED_VALUE` (confirmed by reading
`readTabValues.ts`/`readTabValuesBatch.ts`, which pass no explicit `valueRenderOption`) — so a
`TIME`-formatted cell returns a string like `"9:30 AM"`, not a numeric serial. `parseClockTimeCell.ts`
is a small local parser for this (decided 2026-08-13: not worth a global render-option change) —
returns `null` for blank, `NaN` for unparseable, else decimal hours-of-day.

Validation rules per slot row (decided 2026-08-12, plus one addition decided 2026-08-13):

1. No activity selected, Clock In and Clock Out both blank → skip, not an entry.
2. No activity selected, Clock In or Clock Out has a value → throw (orphaned time entry).
3. Activity selected, Clock In and Clock Out both blank → 0 hours, skip.
4. Activity selected, only one of Clock In/Clock Out filled → throw.
5. Activity selected, both filled, Clock Out before Clock In → throw.
6. Activity selected, both filled, Clock Out ≥ Clock In → compute hours via [080], emit one
   `TimesheetEntry`. If the computed hours round to 0, skip (valid, nothing to report).
7. Clock In or Clock Out value present but unparseable (non-numeric/non-time garbage) → throw.
8. **(Added 2026-08-13)** Activity name doesn't match any activity currently assigned to the employee —
   this is fine so long as no hours are attached (mirrors rule 1/3's skip behavior); if Clock In or
   Clock Out has a value, throw. Decided explicitly by the user: "this is fine so long as no hours are
   attached. If hours are attached then it needs to Unprocessable error."

All throws use `UnprocessableError`, matching the existing convention (caught by
`mapErrorResponse.ts` → HTTP 422), with a message including **employee name and the specific date** of
the offending entry.

**Flat Rate Shifts reading was folded into this ticket** (2026-08-12 decision — "It needs to happen, I
don't have an idea which leg it should be in"): `readClockInOutFlatRateRows.ts` reads each day's Flat
Rate rows via `Number(cellValue)` (no NaN guard, matching the existing TotalHours-mode convention —
tracked as [077]), skipping zero-quantity and unrecognized-activity rows silently, same as TotalHours
mode.

Related but out of scope: [077] tracks the pre-existing, unrelated bug where the TotalHours-mode read
path silently produces `NaN` instead of throwing on non-numeric input.

## File structure (split from a single file per 2026-08-13 request — "readTimesheetEntries is pretty
long... is there a way to break it up into smaller, more manageable, functions?")

- `readTimesheetEntries.ts` — entrypoint; reads the manifest + tab values once, then delegates to one
  of the two below depending on which manifest shape is populated.
- `readClockInOutEntries.ts` — the week/day loop for ClockInOut manifests, calling the two below per
  day.
- `readClockInOutSlotRows.ts` — the 7+1 validation rules for one day's Hourly slot rows.
- `readClockInOutFlatRateRows.ts` — one day's Flat Rate rows.
- `readTotalHoursEntries.ts` — the original TotalHours-mode week loop, moved unchanged into its own
  file.

## Scope (as implemented)

- `parseClockTimeCell.ts` — local `FORMATTED_VALUE` time-string parser.
- `readClockInOutSlotRows.ts` — all 8 rules above.
- `readClockInOutFlatRateRows.ts` — Flat Rate Shifts reading.
- `readClockInOutEntries.ts` / `readTimesheetEntries.ts` — wiring, per the file-split above.
- Unit tests: `parseClockTimeCell.test.ts` (6 tests), plus
  `readTimesheetEntries.clockInOut.test.ts` (14 tests against the real `readTimesheetEntries`
  entrypoint) covering all 8 rules, holiday flagging, Flat Rate nonzero/blank, and combined
  Hourly+FlatRate reads for one day.
