# [066] Validation: Active employee must have at least one activityRate

**Board status:** Ready
**Part of:** [048] Expand EmployeeActivityRates (Epic)
**Depends on:** [051]

## Background

**This is `blackwell-backend` work.**

[055] added a hard requirement that an employee needs at least one `EmployeeActivityRates` bridge row to be included in timesheet generation — "what are we creating a timesheet for otherwise?" That check only runs at generation time, which means a bookkeeper can save an Active employee with zero activities and not find out until a pay period is generated, possibly weeks later.

Decided in follow-up discussion: enforce the same rule earlier, at Employee create/update time — but only for `Active` employees. An `Inactive` employee (mid-offboarding, or a shell record created before activities are assigned) should still be allowed to have zero activities, since `generateTimesheets`/pay-period snapshots already exclude Inactive employees entirely. The [055] generation-time check stays as-is — this is additive (fail fast), not a replacement.

## Scope

- `createEmployee.ts` — if `status === Active` and `activityRates.length === 0`, throw `UnprocessableError` naming the employee (same style as the existing duplicate-`activityId`/activity-not-found checks in this file)
- `updateEmployee.ts` (or `reconcileEmployeeActivityRates.ts`) — same check, applied to the updated employee's `status`/`activityRates`
- Extend unit tests for both services to cover the new validation
