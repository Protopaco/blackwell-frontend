# [072] Rename updateClient to reflect its actual (identity-only) scope

**Board status:** Backlog

## Background

**This is `blackwell-backend` work.**

`createClient` provisions an entire client end to end — Drive folders, the PayrollConfig workbook and all its tabs, and Settings. `updateClient`, by contrast, only ever touches `clientName`/`clientCode`/`status` — everything else (including Settings, which isn't editable through any endpoint yet) is out of scope. The name `updateClient` implies parity with `createClient`'s full scope, which is misleading; it's really closer to "updateClientInfo," matching the frontend's `ClientInfoManagement` page ([062]) that calls it.

Purely a naming clarity issue, not a functional bug — came up in passing while confirming [071]/[070]'s scope.

## Scope

- Rename `src/services/client/updateClient.ts` (and its export, route wiring, and test file) to something that reflects the identity-only scope, e.g. `updateClientInfo`
- Low priority / nice-to-have — no functional change
