# [055] EmployeeActivityRates in timesheet generation + activity-required validation

**Board status:** Backlog
**Part of:** [048] Expand EmployeeActivityRates (Epic)
**Depends on:** [049], [054]

## Background

**This is `blackwell-backend` work.**

`generateTimesheets.ts` currently assumes every employee gets every activity — it computes the pay period's activity list once and applies it to every employee's timesheet loop, with no per-employee filter. That assumption needs to go away: each employee's timesheet should only show the activities they have a bridge row for.

Decided in epic discussion: an employee must have at least one bridge row (activity) to be part of a pay period at all — "what are we creating a timesheet for otherwise?" This is a hard requirement, not an edge case to silently handle.

## Scope

- `generateTimesheets.ts` — filter each employee's activity rows from their `EmployeeActivityRates` bridge rows (via the pay-period snapshot from [054]) instead of the pay period's full activity list
- `sortActivities.ts` — branch on the bridge row's `payRateType` instead of `isFlatRate(activity.payRate)` (coordinating with [052], which removes the old field/enum)
- `readTimesheetEntries.ts` — currently copies `activity.payRate` onto each `TimesheetEntry`; switch to the bridge row's `payRateType`
- New validation: an employee with zero bridge rows (no activities at all) cannot be included in timesheet generation — surface a clear error naming the employee, checked upfront before the per-employee loop (same style as the existing missing-`timesheetFileId` upfront check)
- Decide/implement: does `addEmployeeToPayPeriod` validate bridge coverage at add-time, or only get caught at generation time? (Recommend catching at generation time to keep add-time simple, but flag for confirmation.)
