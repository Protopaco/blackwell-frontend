# [056] Update allocation calc to use EmployeeActivityRates + holidayPayRate

**Board status:** Backlog
**Part of:** [048] Expand EmployeeActivityRates (Epic)
**Depends on:** [054], [055]

## Background

**This is `blackwell-backend` work.**

`resolveDollarRate` in `src/services/payrollReport/buildAllocationRows.ts` is the one place an employee's rate and an activity's rate/type get combined into a dollar figure — today it switches on `activity.payRate` to pick `employee.hourlyPayRate1`, `employee.hourlyPayRate2`, or `activity.flatRateAmount`. This needs to become a bridge-row lookup instead.

Also: `holidayPayRate` has never actually been wired into any calculation (dead field today). This ticket wires it in for real — holiday-flagged hours use the relevant bridge row's `holidayPayRate` instead of its normal `payRate`.

Salary (`payRateType: salary`) is explicitly out of scope here — see [057].

## Scope

- Rewrite `resolveDollarRate` to look up the `EmployeeActivityRates` bridge row for the given `(employeeId, activityId)` pair and use its `payRateType`/`payRate` for `hourly`/`flatrate` rows
- When a timesheet entry/row is flagged as a holiday, use the bridge row's `holidayPayRate` instead of `payRate` for the dollar calc
- `buildSummaryRows.ts` — currently groups by `entry.payRate` (the activity's pay-rate type); update to use the bridge row's `payRateType`
- `payRateType: salary` rows should not be handled by this function's normal hourly/flatrate math — leave a clear seam (e.g. skip/delegate) for [057] to fill in
