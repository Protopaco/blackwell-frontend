# [067] Cascade-delete EmployeeActivityRates rows when an Activity is deleted

**Board status:** Ready
**Part of:** [048] Expand EmployeeActivityRates (Epic)
**Depends on:** [049]

## Background

**This is `blackwell-backend` work.**

`deleteActivity.ts` removes an Activity's row from the client's PayrollConfig `Activities` tab, but doesn't touch `EmployeeActivityRates` — any bridge rows still pointing at that `activityId` are left orphaned. Those dangling rows would keep surfacing in `employee.activityRates` (via `joinEmployeeActivityRates`) even though the underlying activity no longer exists, and would need to be manually cleaned up in the sheet.

Scoped to the master PayrollConfig only — already-generated pay-period snapshots ([054]) are point-in-time copies and are not touched by a later master-config activity deletion, consistent with how snapshots already behave for other master-config edits.

## Scope

- `deleteActivity.ts` — after deleting the Activity row, also remove any `EmployeeActivityRates` rows referencing that `activityId`. Reuse the read → filter → clear → rewrite pattern already established in `reconcileEmployeeActivityRates.ts` (not per-row deletes), for consistency and to keep this a single extra read + clear + write rather than N API calls
- Extend `deleteActivity.ts`'s unit tests to cover the cascade
