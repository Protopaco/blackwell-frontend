# [059] Client Management Workflow (Epic)

**Board status:** Ready (epic — tracked as a group, broken into tickets 060-062)
**Supersedes:** [005] Create Client Management Workflow

## Background

No frontend surface exists yet for creating a client or editing client identity/status. Backend already supports `GET`/`POST /api/v1/client` and `PUT /api/v1/client/{clientId}` — this epic is purely frontend.

Backend client creation is heavier than other creates — it provisions real Drive/Sheets infrastructure (Payroll Config file, Pay Period Registry file, required config tabs, seeded Settings) and deliberately does **not** roll back partial Drive setup on failure. There is also deliberately no delete flow; deactivation via `status` is the only supported removal path (same pattern as Timesheet Folder Management).

Resolved via design discussion:

- **Entry point**: "+ New Client" button in `Header`, next to `ClientSelector` (not folded into the Autocomplete dropdown — that component is typed strictly on real `Client` objects, so injecting a synthetic option is more awkward than a plain adjacent button).
- **Create**: a dedicated page at `/client/new` (not a dialog — there's no list page to anchor one to, since no client is selected yet at this point).
  - Identity fields: `clientName`, `clientCode`
  - Employee Payroll Folder (required): radio choice — "Create new" (default) vs. "Use existing link". Create-new also needs a parent-folder link (`rootFolderLink`).
  - Payroll Config Folder / Payroll Report Folder: collapsed behind an "Advanced" toggle, same radio pattern — omitting either means create-new, matching the backend's default.
  - Settings fields: `timeInputMethod`, `payPeriodInterval`, `payPeriodStartDate`
  - Because the backend doesn't roll back partial failures, an error after Drive provisioning has started needs a clear, specific message (not a generic toast) — something like "some Drive resources may already have been created — check before retrying."
- **Edit**: a button on the existing `ClientSummary` page opening a dialog (matching the existing employee/activity edit dialog pattern) for `clientName`/`clientCode`/`status` only. No delete.

## Scope

Broken into:

- [060] "+ New Client" entry point — Header button + `/client/new` route scaffold
- [061] Client Create page — full form, submit, partial-failure-aware error messaging
- [062] Edit Client dialog on `ClientSummary`

Each of 060-062 can ship independently, though 061 depends on 060's route existing.
