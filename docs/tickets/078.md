# [078] Generate clock-in/clock-out timesheets

**Board status:** Backlog
**Reported:** 2026-08-12
**Implemented:** 2026-08-13

## Background

**This is `blackwell-backend` work.**

First piece of adding a second timesheet entry mode alongside the existing "enter number of hours"
mode. `Settings.timeInputMethod` (`TotalHours` | `ClockInOut`) is a per-client, required setting —
validated on client creation, editable via `ClientSettingsFields.tsx`. `generateTimesheets.ts` branches
on it: `TotalHours` clients keep the existing stacked-per-week layout (`buildWeek.ts`); `ClockInOut`
clients get an entirely different layout, built by `buildClockInOutTimesheet.ts`.

**Layout, as actually built** (this diverged from the original per-week design during implementation —
see the 2026-08-12/08-13 decisions below): weeks sit **side by side**, not stacked. Every week in the
pay period shares the same row numbers; each week gets its own 4-column group
(`activity/In/Out/Total`, `CLOCK_IN_OUT_WEEK_COLUMN_WIDTH = 4`) at a `labelColumnIndex` computed as
`weekIndex * (CLOCK_IN_OUT_WEEK_COLUMN_WIDTH + CLOCK_IN_OUT_SPACER_COLUMN_WIDTH)`, separated by a
1-column spacer. This works because pay periods are always a whole number of weeks and every week has
the same day count — so the row sequence only needs to be computed once and reused per week's column
group.

Per day, the block is: a day header row (day name + date), a column header row
(`Hourly`/`In`/`Out`/`Total`), `CLOCK_IN_OUT_SLOTS_PER_DAY` (6) generic entry-slot rows (activity
dropdown + Clock In + Clock Out + a display-only Total formula), and — **when the employee has any
flat-rate activities** — that same day's own Flat Rate section directly below the slots (a section
label row plus one row per flat-rate activity, with In/Out merged into one "Shifts" cell). This
replaced the original once-per-week Flat Rate design after live review: "Flat Rate needs to be there
for every day. When both are present each day will have an Hourly and FlatRate section." A blank break
row separates each day's block from the next (not after the last day).

The slot Total formula (`MROUND((Out-In)*24,0.25)`) is **display-only**, for employee/supervisor
visibility — the authoritative hours calculation happens at read time (see [079]/[080]).

`TimesheetManifest.clockInOutWeeks?: ClockInOutWeekManifest[]` is set instead of `weeks` when the
client's `timeInputMethod` is `ClockInOut` — a timesheet is consistently one shape or the other, never
mixed:

```ts
interface ClockInOutSlotRowManifest {
  row: number;
}
interface ClockInOutFlatRateRowManifest {
  activityId: Guid;
  activityName: string;
  row: number;
}
interface ClockInOutDayManifest {
  date: string;
  dayHeaderRow: number;
  columnHeaderRow: number;
  slotRows: ClockInOutSlotRowManifest[];
  flatRateSectionLabelRow?: number;
  flatRateRows: ClockInOutFlatRateRowManifest[];
}
interface ClockInOutWeekManifest {
  weekIndex: number;
  labelColumnIndex: number;
  weekLabelRow: number;
  days: ClockInOutDayManifest[];
}
// on TimesheetManifest:
clockInOutWeeks?: ClockInOutWeekManifest[];
```

## Formatting (built as part of this ticket, iterated through several rounds of live review)

- Activity dropdown columns widened to `CLOCK_IN_OUT_ACTIVITY_COLUMN_WIDTH = 250`px.
- Week label row styled `SECONDARY` (not the stronger `PRIMARY_DARK`).
- Hourly slot rows and Flat Rate rows zebra-stripe between `MUTED` and `PRIMARY`, restarting at index 0
  for each section instance (each day's Hourly section and each day's Flat Rate section stripe
  independently).
- Both the Hourly column-header row and the Flat Rate section-label row are left-aligned (reuses the
  `dailyTotalRow` style, not the centered `sectionLabelRow` style).
- A thick (`SOLID_THICK`, width 3) `PRIMARY_DARK` border box wraps each day's whole block (Hourly slots
  plus Flat Rate section if present) — `outlineBlockBorder.ts` gained an optional `thick` parameter for
  this.
- In/Out cells are formatted as time (`hh:mm AM/PM`).
- Time-entry data validation on In/Out cells: `CUSTOM_FORMULA`, `strict: true`, requiring blank or a
  real time-of-day fraction (`ISNUMBER(cell) AND cell>=0 AND cell<1`) — tightened after live testing
  found that plain typed numbers (e.g. `2`, `5`) passed an earlier `ISNUMBER`-only check and produced
  nonsense hours (`MROUND((5-2)*24,0.25) = 72`).

## Scope (as implemented)

- `TimesheetManifest.ts` — the types above.
- `rowBuilders.ts` — `buildClockInOutWeekLabelRow`, `buildClockInOutDayHeaderRow`,
  `buildClockInOutColumnHeaderRow`, `buildClockInOutSlotRow`, `buildClockInOutFlatRateSectionLabelRow`,
  `buildClockInOutFlatRateActivityRow`.
- `buildClockInOutTimesheet.ts` — builds every row for the whole pay period in one call (side-by-side
  week columns, per-day Flat Rate, break rows).
- `generateTimesheets.ts` branches on `timeInputMethod` to choose `buildClockInOutTimesheet` vs.
  `buildWeek`.
- `config/constants.ts` — `CLOCK_IN_OUT_SLOTS_PER_DAY`, `CLOCK_IN_OUT_WEEK_COLUMN_WIDTH`,
  `CLOCK_IN_OUT_SPACER_COLUMN_WIDTH`, and the four `CLOCK_IN_OUT_*_COLUMN_OFFSET` constants (live here,
  not in `rowBuilders.ts`, since `formatClockInOutTimesheet.ts` and `generateTimesheets.ts` also need
  them).
- `src/utils/timesheetTheme.ts` — `CLOCK_IN_OUT_ACTIVITY_COLUMN_WIDTH`.
- `formatting/formatClockInOutTimesheet.ts` and `formatting/rowStyles.ts` (`mutedDataEntryRow`,
  `primaryDataEntryRow`) — all formatting described above.
- `formatting/outlineBlockBorder.ts` — added `thick` parameter.
- Manifest persisted via the existing `saveManifest`/`appendManifest` path, unchanged.

## Resolved

- Slot-count constant: `CLOCK_IN_OUT_SLOTS_PER_DAY = 6`.
- Formula-error handling for half-filled slots on the sheet itself: not specially handled — the sheet's
  Total formula is cosmetic only, and [079]'s read-time validation is authoritative, so a `#VALUE!`-type
  display glitch mid-entry was accepted as low-priority and not addressed.
