# [080] Calculate hours from clock-in/clock-out times

**Board status:** Backlog
**Reported:** 2026-08-12
**Implemented:** 2026-08-13

## Background

**This is `blackwell-backend` work.**

Third piece of adding the clock-in/clock-out timesheet mode. A small, pure calculation split out of
[079] so it's independently testable: given a Clock In time and a Clock Out time (Clock Out ≥ Clock In,
already validated by [079]), compute the elapsed hours rounded to the nearest 15 minutes (decided
2026-08-12).

Not a concern for this phase (per requirements discussion 2026-08-12): break deduction, multiple
in/out pairs per day, overnight shifts (Clock Out on the following calendar day). All out of scope here
— this is a same-day, single-pair calculation only. A comment on the function should note these as
known simplifications if/when the "more than one slot" or "overnight" cases are picked up later, so a
future reader isn't surprised by the narrow scope.

## Scope (as implemented)

- `calculateClockInOutHours.ts` — a single pure function, no I/O, no Sheets access:
  ```ts
  const elapsedHours = clockOutHours - clockInHours;
  return Math.round(elapsedHours * 4) / 4;
  ```
  Takes decimal-hours-of-day (as produced by [079]'s `parseClockTimeCell`) for Clock In/Out, already
  validated `clockOut >= clockIn`, and returns hours rounded to the nearest quarter hour.
- Rounding at the boundary: standard round-half-up (`Math.round`), no payroll-specific convention
  needed.
- Unit tests (`calculateClockInOutHours.test.ts`, 5 tests): exact quarter hours, round-down, round-up,
  exact-tie round-half-up, and a same Clock In/Clock Out time (0 hours) — a 0-hours result is skipped by
  [079]'s slot-row reading rather than emitted as an empty `TimesheetEntry`.
- Known simplifications, noted in a doc comment on the function per the original scope: no break
  deduction, one In/Out pair only, no overnight shifts. Still true as implemented — none of these were
  picked up.
