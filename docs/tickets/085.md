# [085] Frontend — grouped/reordered activities management UI

**Board status:** Backlog
**Reported:** 2026-08-17

**Depends on [084]** (backend) — needs `groupLabel`/`sortOrder` on the `Activity` model and the
regenerated OpenAPI spec before the client can be regenerated.

## Background

See [084] for the full resolved design (one-level grouping, ungrouped-first-then-alphabetical-groups
ordering, no separate `GroupLabel` entity). This ticket is the Activity Management UI work: letting users
set an activity's group and manually reorder activities, so the generated timesheet in [084] actually
reflects what they configure.

**Resolved design (2026-08-17):**

- `groupLabel` input is a **free-solo autocomplete** in the Activity create/edit dialog — options sourced
  from the distinct `groupLabel` values already used across that client's other activities, but the user
  can still type a new one. No separate "manage groups" screen.
- Reordering uses drag-and-drop, following
  [MUI X Data Grid's row-ordering pattern](https://mui.com/x/react-data-grid/row-ordering/) as the
  reference interaction (the row-ordering *behavior* — this codebase doesn't use Data Grid elsewhere, so
  this doesn't imply pulling in the whole Data Grid component; see chunk 3 below).
- **Save All, not save-on-drop** (2026-08-17): dragging updates local/pending order state only; nothing is
  persisted until the user clicks an explicit "Save All" button. Mirrors the staged-edit + "Save All"
  pattern already used in `PayrollReportPage.tsx` (`editedWageValues`/`editedTaxValues` + dirty-diff + save
  button) — reordering is naturally a multi-move session, not a series of isolated single-field edits.
- **Persists via the new batch endpoint, not one call per activity** (2026-08-17, see [084]): "Save All"
  sends one `PUT /api/v1/activity/{clientId}/batch` request with `{activityId, groupLabel, sortOrder}` for
  every activity whose position actually changed from the server's last-known state — not N individual
  single-activity `PUT` calls. [084] added this endpoint specifically because the existing single-activity
  `PUT` does a full read-modify-write of the client's whole Google Sheets workbook per call, and a bulk
  reorder easily touches many activities at once.
- **Column-header sorting is removed from this table** (2026-08-17): drag-and-drop reordering and
  click-to-sort-by-column are contradictory — the table is always in the grouped/custom-order view
  described above, matching [084]'s rules, with no sortable column headers.

## Implementation plan

Broken into 3 sequential chunks — stop after each for review before starting the next.

1. **Frontend generated client regen** — once [084] lands, regenerate `src/api/generated/**`.
2. **Activity dialog** — add the free-solo `groupLabel` autocomplete and `sortOrder` handling
   (auto-assigned on create, preserved on edit) to `ActivityDetailsFields.tsx`/`ActivityDialog.tsx`.
3. **Activities table** — rework `ActivitiesTable.tsx` for grouped/ordered rendering (no column sorting),
   drag-and-drop reordering into pending local state, a "Save All" button that persists whatever changed
   via one call to the new `PUT /api/v1/activity/{clientId}/batch` endpoint ([084] chunk 4). Decide the
   dashboard `ActivityRow`/`ActivitiesCard` question in the same pass.
