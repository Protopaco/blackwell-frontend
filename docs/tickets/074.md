# [074] Timesheet formatting redesign — RowStyle layer + section labeling

**Board status:** Ready

## Background

**This is `blackwell-backend` work.**

Found via manual testing: flat-rate activity rows (e.g. "Administration" configured as `FlatRate` for a
given employee) render identically to hourly activity rows in the generated timesheet, with no section
label distinguishing them, inconsistent blank-row spacing, and no Daily Total row of their own. Root
cause discussion led to a broader design pass — full target design is documented in
`docs/TIMESHEET_STYLE_GUIDE.md`, which this ticket implements.

Also identified along the way: the current formatting code (`src/services/timesheet/formatting/*`)
hand-assembles raw `repeatCell`/`updateBorders`/`setDataValidation` request objects per row type, with
duplicated fill/border/validation logic and an error-prone `repeatCell` `fields` mask that's easy to get
out of sync with the actual style (this is how the stale "flat-rate rows get different holiday colors"
comment in `formatActivityRows.ts` went unnoticed — the comment described behavior the code never
actually implemented). This ticket introduces a declarative `RowStyle` layer to fix that class of bug
going forward, alongside the structural changes.

## Scope

Everything below is fully specified in `docs/TIMESHEET_STYLE_GUIDE.md` — read that first.

### 1. `RowStyle` layer (new)

- New `RowStyle` type + named style definitions (e.g. `identityRow`, `weekLabelRow`, `dayOfWeekRow`,
  `sectionLabelRow`, `activityRow`, `dailyTotalRow`, `spacerRow`, `signatureRow`,
  `includeInPayrollRow`, `summaryRow`) — likely alongside `timesheetTheme.ts`
- One generic builder that turns a `RowStyle` + range into the actual `repeatCell`/`updateBorders`/
  `setDataValidation` requests, computing the `fields` mask itself rather than each call site typing it
  by hand
- Migrate existing `format*Rows.ts` files to use it instead of hand-building requests directly

### 2. Structural changes (per the style guide)

- `weekLabelRow` — alter `formatHolidayNameRow.ts` (or its caller) to add the week's date-range label to
  the label cell (`SECONDARY`), leaving existing holiday-name behavior in the rest of the row untouched
- `sectionLabelRow` (new) — "Hourly"/"Flat Rate" label + "Total" header, styled like `dayOfWeekRow`
- Flat Rate section gains its own `dailyTotalRow`, matching Hourly's
- Either section (Hourly or Flat Rate) is fully omitted for a week if the employee has zero activities of
  that type that week — no label row, no activity rows, no daily total row
- `spacerRow` (reuses existing `formatDividerRows.ts`) only appears between the two sections when both
  are present that week
- Fix the stale `formatActivityRows.ts` comment — holiday-column coloring stays consistent across Hourly
  and Flat Rate sections (no behavior change, comment-only fix)
- New block-level borders around each block's full bounding range: Summary (`SECONDARY`), Week
  (`PRIMARY_DARK`), Approval (`MUTED`), Totals (`MUTED`) — all medium width, none of this exists today
  (only individual rows are bordered currently)

### 3. Likely-affected files

`buildWeek.ts`, `formatWeekSection.ts`, `formatHolidayNameRow.ts`, `formatActivityRows.ts`,
`formatDailyTotalRow.ts`, `formatDividerRows.ts`, `rowBuilders.ts`, `applyTimesheetFormatting.ts`,
`TimesheetManifest.ts` (model may need new row-position fields for the new row types), plus new files for
the `RowStyle` layer. Existing unit tests for these will need updates; new tests for the new row types
and the zero-activity-section-omission rule.
