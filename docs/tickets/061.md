# [061] Client Create page

**Board status:** Backlog
**Part of:** [059] Client Management Workflow (Epic)
**Depends on:** [060]

## Background

See [059] for the full field/UX design. This is the first frontend UI to need an "existing link vs. create new" folder-choice pattern — no existing component to reuse (`TimesheetFolder` creation only ever takes a link, no create-new option).

## Scope

- Build the `/client/new` page, replacing [060]'s placeholder
- Identity fields: `clientName`, `clientCode`
- Employee Payroll Folder (required): radio — "Create new" (default, needs a parent `rootFolderLink`) vs. "Use existing link"
- "Advanced" collapsed section: same radio pattern for Payroll Config Folder and Payroll Report Folder (each optional — omitted means create-new)
- Settings fields: `timeInputMethod`, `payPeriodInterval`, `payPeriodStartDate`
- Submit wired to `POST /api/v1/client` via the generated `clientApi`
- On success, navigate to the new client (e.g. `/client/:clientId`)
- Error handling: since the backend does not roll back partial Drive/Sheets provisioning on failure, a failed submission needs a specific message warning that partially-created Drive resources may exist and should be checked before retrying — not a generic error toast
