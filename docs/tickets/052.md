# [052] Update Activity — remove payRate/flatRateAmount

**Board status:** Backlog
**Part of:** [048] Expand EmployeeActivityRates (Epic)

## Background

**This is `blackwell-backend` work.**

Pay rate and rate amount move to the `EmployeeActivityRates` bridge ([049]) — each employee-activity pair now carries its own `payRateType`/`payRate`. `Activity.payRate`/`flatRateAmount` become meaningless once every pairing has its own rate. No back-compat needed — pre-launch.

Note: `Activity.payrollCategory` (`Regular`/`ETO`/`PTO`/`STO`) is a different concept (time-off category) and is unaffected — only the old `PayRate` enum (`Hourly1`/`Hourly2`/`FlatRate1`/`FlatRate2`) and `flatRateAmount` are being removed from Activity.

## Scope

- Remove `payRate`, `flatRateAmount` from `Activity`, `ActivityCreateRequest`/update request, `ACTIVITIES_HEADERS`, `mapActivity.ts`/`mapActivityRow.ts`, swagger schemas
- Remove the old `PayRate` enum (`src/models/PayRate.ts`) and its `isFlatRate()` helper — replaced by the bridge's `payRateType` (built in [049])
- Update everywhere `isFlatRate(activity.payRate)` was used to branch timesheet behavior (`sortActivities.ts`, `generateTimesheets.ts`) — these need to look up the relevant bridge row's `payRateType` instead. Coordinate with [055], which owns wiring the bridge into timesheet generation — this ticket should remove the old field/enum; [055] does the behavioral rewire.
- Update `createActivity.ts`/`updateActivity.ts` services accordingly
- `updateActivityOnPayPeriod.ts` currently locks `payRate`/`flatRateAmount` as "structural" fields once a pay period's first timesheet exists — that locking rule moves to the bridge row ([054]), remove it from here
